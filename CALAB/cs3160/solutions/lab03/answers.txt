## 1.3  Two questions, one sentence each.

# Why does a 1 KiB cache help a program whose instructions do not fit in 1 KiB?
Q1: Because only the part being executed right now has to fit. A loop body is
#   fetched from RAM once and then hit on every later iteration, and one 64-byte
#   block holds sixteen instructions, so even straight-line code pays RAM once
#   per sixteen fetches. A cache holds the working set, not the program.

# Which program benefits least, and what is different about it?
Q2: 8-arith-edges -- 3.53x, against 4.44x to 8.15x for the rest. Two things set
#   it apart. 100 of its 371 instructions touch memory, 86 of them stores, and
#   this is an *instruction* cache, so none of that traffic is cached at all.
#   And it is the only one that fills the cache: 16 distinct blocks for 16 sets,
#   so its fetches start conflicting -- 26 misses with 10 evictions, where the
#   other four touch 5 blocks each and miss 6 or 7 times. Worth saying out loud
#   that it does not have the lowest hit rate -- 2-prime does, at 90.54% --
#   because a hit rate is not a speedup.
